# AgentDot 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 macOS 上构建 AgentDot——一个置顶悬浮球，实时显示 Claude Code CLI 会话状态：运行中绿色跑马灯，等待授权红色脉冲，并可精确跳转到 iTerm2 / Terminal / Kaku / Ghostty 的对应标签页/面板。

**Architecture:** SwiftPM 包拆成三个 target：`AgentDotCore`（模型、状态机、文件存储、终端上下文、settings 合并）、`DotHook`（Claude Code hook helper CLI）、`AgentDotApp`（AppKit NSPanel + SwiftUI）。hook 独占写每会话 JSON，app 只读并按聚合状态渲染；app 独占写 `ui-state.json` 保存消警状态。

**Tech Stack:** Swift 6.4.2（Swift 5 language mode）、SwiftPM、AppKit、SwiftUI、Foundation、Darwin/libproc、NSAppleScript、Kaku CLI。无第三方依赖、无 Xcode。

**Spec:** `docs/2026-11-25-AgentDot悬浮球/2026-11-25-AgentDot悬浮球-技术方案.md`（v1.3，D1–D15 为契约）

## Global Constraints

- 只接 Claude Code CLI；不做 DSH、WorkBuddy 或其他工具。
- macOS 13+；Swift 6.4.2，Package 使用 `.v5` language mode；只用 Command Line Tools 的 `swift build` / `swift test`，不依赖 Xcode。
- 无第三方依赖；不联网；不读取也不保存 prompt、tool_input、tool_response、notification message、last_assistant_message。
- 路径固定：
  - App：`~/Applications/AgentDot.app`
  - helper：`~/.agent-dot/bin/dot-hook`
  - 状态：`~/Library/Application Support/AgentDot/`（`sessions/`、`config.json`、`ui-state.json`、`logs/`）
  - bundle id：`dev.agentdot.app`
- 10 个 hook 事件：`SessionStart`、`UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`PermissionRequest`、`PermissionDenied`（可选增强）、`Notification`、`Stop`、`StopFailure`、`SessionEnd`。
- 状态枚举：`idle`、`running`、`waiting_permission`、`done`、`error`、`ended`；聚合优先级：未消警 waiting > 已消警 waiting > error > running > done > idle。
- 视觉：运行中绿色跑马灯（左→右 1.8s 循环）；等待授权红色脉冲；完成绿色常亮；失败琥珀色；空闲灰色；无声音、无系统通知；界面中文。
- 收起态阈值 N：1–9，默认 5；≤N 显示 3×3 内的彩色小点，>N 显示总数数字。
- 授权消警：只有当该会话所在标签页/面板成为活动时才自动消警；无法精确确认的终端不自动消警，保留手动“忽略本次提醒”。绝不代答授权。
- hook 契约：5 秒超时；`emit` 不输出 stdout；任何错误 exit 0；sidecar `<id>.lock` + `flock`；临时文件 + rename 原子写。
- settings 合并：备份 `settings.json.agentdot-backup-<yyyyMMdd-HHmmss>`；只增删 command 包含 `.agent-dot/bin/dot-hook` 的 handler；保留现有 `cc-status` 和其他 hooks。
- **禁止 `git commit` / `git push`**：用户自己手动提交。每个任务以 `swift build`/`swift test` 或手工验证结束，不包含 git 提交步骤。
- 性能目标：hook 单次 < 50ms；App 空闲 CPU < 1%；内存 < 80MB；运行中 500ms 轮询、5s 存活检查、等待授权时 1s 活动标签检查。

## Review Focus

以下是最容易被真实使用打到的五类情况，每个都在对应 Task 的测试里钉住：

1. **任务完成后立刻关标签页**：`done` 行必须在 `SessionEnd` 时 3 秒内消失，或在进程检查兜底时最多约 8 秒消失；不能残留绿色“已完成”。测试在 Task 8 的 `SessionVisibilityTests`，手工验证在 Task 12。
2. **批准长命令后红闪不停**：没有“已批准”事件；脉冲只能在该会话的标签页/面板精确成为活动时停止，不能因为“终端 app 在前台”就消警。测试在 Task 10 的 `AcknowledgmentPolicyTests`。
3. **同一终端开着多个标签页**：后台标签里的授权不能被前台的另一个标签页消警。测试在 Task 10，手工验证在 Task 12。
4. **已有 `cc-status` hooks 和 symlink 配置**：合并必须保留所有现有 handler、生成备份、幂等，卸载只删自己的。测试在 Task 5 的 `SettingsMergerTests`。
5. **未知事件/坏 JSON/新版 hook 字段**：`dot-hook emit` 必须 exit 0、不写坏状态、绝不阻塞 Claude。测试在 Task 2 的 `StateReducerTests` 和 Task 6 的模拟脚本。

- [ ] **Step 3: 实现 reducer**

事件规则（与 spec §5.1/§6.3 一致）：

- `SessionStart`：
  - `startup` / `fork`：state = idle，清 `currentTool`、`turnStartedAt`、`turnEndedAt`、`waitingSince`、`errorKind`。
  - `resume`：若 existing.state ∈ {ended, error, running, waitingPermission} → idle；`done` 保留；`compact` 保留一切。
  - `clear`：state = idle，清 turn/waiting/currentTool/errorKind。
  - 所有 source 都用传入的 `terminal` 覆盖 `terminal`，`updatedAt = now`。
- `UserPromptSubmit`：state = running，`turnStartedAt = now`，`turnEndedAt = nil`，`waitingSince = nil`，`currentTool = nil`，`lastActivityAt = now`。
- `PreToolUse`：若 existing.state == waitingPermission → 保持 waiting（只更新 currentTool/lastActivity）；否则 state = running；`currentTool = payload.toolName`。
- `PostToolUse`：state = running，`currentTool = nil`，`waitingSince = nil`，`lastActivityAt = now`。
- `PermissionRequest`：state = waitingPermission，`waitingSince = now`，`currentTool = payload.toolName`，`turnEndedAt = nil`。
- `PermissionDenied`：state = running，`waitingSince = nil`，`currentTool = nil`。
- `Notification`：`permission_prompt` / `agent_needs_input` → waitingPermission（若 `waitingSince == nil` 则设为 now）；`idle_prompt` → done，`turnEndedAt = now`，清 waiting/currentTool；其他保持原状态。
- `Stop`：state = done，`turnEndedAt = now`，清 waiting/currentTool。
- `StopFailure`：state = error，`turnEndedAt = now`，清 waiting/currentTool，`errorKind = payload.errorType`。
- `SessionEnd`：state = ended，清 waiting/currentTool；若原状态是 running/waiting，`turnEndedAt = now`。
- 所有已知事件：`updatedAt = now`；`lastActivityAt` 在除 SessionEnd 外更新（SessionEnd 也可更新）。
- existing == nil 时创建 baseline：`schema=1`、`sessionID`、`cwd = payload.cwd ?? ""`、`projectName = SessionState.projectName(...)`、`state = .idle`、`startedAt = now`、`updatedAt/lastActivityAt = now`、`terminal` 传入值。

`HookPayload` 的 CodingKeys：`session_id`、`hook_event_name`、`tool_name`、`tool_use_id`、`notification_type`、`error_type`；`cwd`/`source`/`reason` 同名。

```bash
#!/usr/bin/env bash
set -euo pipefail
ROOT="$(cd "$(dirname "$0")/.." && pwd)"

```

```bash
#!/usr/bin/env bash

rm -rf "$HOME/Applications/AgentDot.app"

```
