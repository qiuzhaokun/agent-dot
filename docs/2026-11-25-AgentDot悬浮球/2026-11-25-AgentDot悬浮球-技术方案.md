# AgentDot 悬浮球 — 技术方案

- 日期：2026-11-25
- 仓库：https://github.com/qiuzhaokun/agent-dot
- 分支：`feature/2026-11-25-agent-dot`
- 状态：已确认（2026-11-25，D1–D15 生效；执行计划见同目录 `2026-11-25-AgentDot悬浮球-执行计划.md`）

## 1. 背景与目标

用户在一台 Mac 上同时运行多个 Claude Code CLI 会话，分别在不同终端窗口/标签页里执行任务。当前的问题是：

- 需要不断切换窗口才能知道每个会话是在跑、跑完了、还是卡在授权提示上；
- 授权提示出现时人可能在看别的窗口，任务会一直空等。

目标：做一个常驻在所有普通窗口之上的悬浮小球（类似老 iOS AssistiveTouch）：

- 收起态一眼看出有几个会话、有没有需要处理的；
- 展开后按会话列出状态和进度；
- 运行中的会话显示绿色跑马灯（从左往右循环）；
- 某个会话等待授权时，对应进度条和收起态小球红色闪烁；
- 点击会话行直接跳回对应的终端标签页/面板。

## 2. 范围

### 2.1 In scope

- 只接入 **Claude Code CLI**（当前版本 2.1.332）。
- 悬浮小球：置顶、跨 Space、全屏可见、可拖动、贴边吸附、位置记忆。
- 收起态：≤N 个会话显示彩色小点，>N 显示总数；N 可设置，默认 5。
- 展开面板：会话列表、状态、当前工具、已用时、跑马灯/红闪。
- 点击跳转：iTerm2、Terminal.app、Kaku、Ghostty。
- 设置：阈值 N（1–9）、开机自启、修复 Hooks、打开状态目录。
- 安装/卸载脚本，自动合并 Claude Code hooks。
- 本地单元测试 + 手工终端矩阵验证。

### 2.2 Out of scope

- DeepSeek Harness、WorkBuddy 及其他 AI 工具。
- 提示音、系统通知、横幅。
- 历史记录、统计报表、云端同步、多设备。
- 自动批准/代答授权（AgentDot 只观察，不介入授权流程）。
- 精确的 tmux pane 切换（只跳到外层终端标签页；如后面需要再加）。
- 多显示器分别显示多个小球（单球，可拖到任意屏幕）。

## 4. 总体架构

```
Claude Code CLI (2.1.332)
  │  10 个 hook 事件，stdin 传 JSON
  ▼
~/.agent-dot/bin/dot-hook emit
  ├─ 解析事件 + session_id/cwd/tool_name
  ├─ 首次事件解析终端上下文（env + 父进程 + tty）
  ├─ flock 串行化同一 session 的读-改-写
  └─ 原子写 → ~/Library/Application Support/AgentDot/sessions/<id>.json

AgentDot.app
  ├─ SessionStore：500ms 轮询 sessions/，解码 + 去重 + 清理（只读会话 JSON）
  ├─ UIStateStore：ui-state.json（消警/隐藏），app 独占写
  ├─ AggregateState：未消警的等待授权 > 失败 > 运行中 > 完成 > 空闲
  ├─ 悬浮 NSPanel（收起小球 / 展开列表）
  ├─ 动画：绿色跑马灯、红色脉冲
  ├─ TerminalJumper：osascript / kaku cli
  └─ 设置：阈值 N、开机自启、修复 hooks
```

关键点：**hook 只负责写状态，不阻塞 Claude**；app 崩溃/重启不影响状态；hook 失败只写本地错误日志，永远 exit 0。

## 5. Hook 接入

### 5.1 事件与状态映射

| 事件 | matcher | 用到的字段 | 状态变化 |
|---|---|---|---|
| `SessionStart` | 省略（全部 source） | `source` | `startup`/`fork`：新建或更新，idle；`resume`：重解析终端与 pid，ended/error/running/waiting→idle，done 保留；`clear`：重置 idle；`compact`：保留状态 |
| `UserPromptSubmit` | 无 matcher 支持 | 无（不读 prompt） | running，current_tool = nil，设置 turn_started_at |
| `PreToolUse` | 省略（全部工具） | `tool_name` | 非 waiting 时 running，current_tool = tool_name；当前是 waiting_permission 时只更新 current_tool/last_activity，**不改变 state、不清 waiting**（它不代表授权已批准，见下方时序） |
| `PostToolUse` | 省略（全部工具） | `tool_name` | running，current_tool = nil，刷新 last_activity；如在等授权，视为已处理并清除 |
| `PermissionRequest` | 省略（全部工具） | `tool_name`、`tool_use_id` | waiting_permission，设置 waiting_since；记录 tool_name（不存 tool_input） |
| `PermissionDenied` | 省略（全部工具） | `tool_name`（如有） | running（清除 waiting；后续 `Stop` 会置 done）；该事件在 2.1.332 存在，作为可选增强 |
| `Notification` | 省略（全部类型） | `notification_type` | `permission_prompt` / `agent_needs_input` → waiting_permission；`idle_prompt` → done；其他忽略 |
| `Stop` | 无 matcher 支持 | 无（不读 last_assistant_message） | done，current_tool = nil，设置 turn_ended_at |
| `StopFailure` | 省略（全部错误类型） | 错误类型（如有） | error，记录 error_kind，设置 turn_ended_at |
| `SessionEnd` | 省略（全部 reason） | `reason` | ended；app 3 秒后移除 |

**关键时序（Claude Code 2.1.332）**：

```
PreToolUse → 授权提示（PermissionRequest）→ 用户允许/拒绝 → 工具执行 → PostToolUse
```

授权提示发生在 `PreToolUse` **之后**，而工具执行完才触发 `PostToolUse`。因此：

- 不能用 `PreToolUse` 清除 waiting_permission；
- 没有“用户已批准”的 hook 事件；
- 长命令（如 `mvn test`）批准后可能几分钟才收到 `PostToolUse`，红闪不能一直持续到那时——需要 §6.3 的 UI 消警机制。

不注册 `SubagentStop`，避免子代理状态污染主会话；主会话的 `Stop` 已经能表达回合结束。子代理的 `PreToolUse`/`PostToolUse` 仍会刷新主会话的 running 状态，这是期望行为。

### 5.2 合并到 settings.json

安装器/“修复 Hooks”按钮执行：

1. 读取 `~/.claude/settings.json`（不存在则 `{}`）。
2. 备份到同目录 `settings.json.agentdot-backup-<yyyyMMdd-HHmmss>`。
3. 解析为 `JSONSerialization` 可变容器，保留所有未知字段。
4. 对每个事件，删除 command 中包含 `/.agent-dot/bin/dot-hook` 的旧 handler（幂等）。
5. 追加本项目的 handler：

```json
{
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "/Users/larry/.agent-dot/bin/dot-hook emit",
            "timeout": 5
          }
        ]
      }
    ]
  }
}
```

> 实际安装时对 10 个事件各追加一条（示例只列 `SessionStart`）；`command` 使用当前用户 home 的绝对路径（无空格）。
> `PermissionDenied` 作为可选增强：安装器先写入并校验，如果当前 Claude Code 版本不认该事件名则跳过并记录，核心流程不依赖它。
> 现有 `cc-status` 的 handler 原样保留，不删除、不重排。

6. 原子写回：同目录临时文件 + `rename`；如果原文件是 symlink，写入其解析后的目标，保留 symlink。
7. 写完后重新读取校验：每个事件至少有一个本项目的 handler，否则报错并提示恢复备份。

卸载：只删除 command 包含 `/.agent-dot/bin/dot-hook` 的 handler；其他 hooks 原样保留。

### 5.3 helper 契约（dot-hook）

- 入口：`dot-hook emit`，从 stdin 读取一个 JSON 对象；stdout **不输出任何内容**，exit 0。
- 无论成功失败都 exit 0（除了 `install-hooks`/`uninstall-hooks`/`status` 子命令），保证绝不影响 Claude。
- 超时由 Claude Code 配置为 5 秒；helper 目标 < 50ms。
- 同一 session 的读-改-写用 **sidecar 锁文件** `sessions/<id>.lock` 上的 `flock` 串行化（不锁 session JSON 本身，避免 rename 换 inode 导致锁失效）；写入用临时文件 + `rename` 原子替换。
- session JSON 由 hook **独占写**；app 永远不写 session JSON，只写自己的 `ui-state.json`。这样 app 的消警/隐藏操作不会回滚 hook 的新状态。
- 错误只写 `~/Library/Application Support/AgentDot/logs/hook.log`（单文件上限 1MB，轮转一次），日志不含 prompt、tool_input、tool_response。
- 子命令：
  - `emit`：hook 入口。
  - `install-hooks`：合并 settings.json。
  - `uninstall-hooks`：移除本项目 handler。
  - `status`：输出当前 sessions 摘要（调试用）。
  - `version`：输出版本。

## 6. 状态模型

### 6.1 Session JSON

路径：`~/Library/Application Support/AgentDot/sessions/<session_id>.json`，目录权限 0700，文件 0600。

```json
{
  "schema": 1,
  "session_id": "abc123",
  "cwd": "/Users/larry/webroot/xbo/datagrip",
  "project_name": "datagrip",
  "state": "waiting_permission",
  "current_tool": "Bash",
  "notification_type": "permission_prompt",
  "error_kind": null,
  "started_at": 1764079200,
  "updated_at": 1764079260,
  "last_activity_at": 1764079260,
  "turn_started_at": 1764079200,
  "turn_ended_at": null,
  "waiting_since": 1764079260,
  "terminal": {
    "app": "iTerm2",
    "tty": "/dev/ttys003",
    "iterm_session_id": "w0t0p0:UUID",
    "term_session_id": null,
    "ghostty_surface_id": null,
    "wezterm_pane": null,
    "tmux_pane": null,
    "claude_pid": 12345,
    "claude_exec_path": "/usr/local/bin/claude"
  }
}
```

约束：

- 不存 `prompt`、`tool_input`、`tool_response`、`last_assistant_message`、`message` 原文。
- `project_name` 取 `cwd` 最后一段；`cwd == $HOME` 时用 `~`。
- `terminal.app` 枚举：`iTerm2` / `Terminal` / `Ghostty` / `Kaku` / `unknown`。
- 所有字符串在读取时做长度限制（cwd ≤ 1024，tool_name ≤ 64，id ≤ 128）。
- `turn_started_at` 由 `UserPromptSubmit` 设置；`turn_ended_at` 由 `Stop`/`StopFailure` 设置；界面上的“已用时”按**当前回合**计算，不是会话生命周期。
- `waiting_since` 在进入 `waiting_permission` 时设置，离开等待态时清空。
- session JSON 由 hook **独占写**；app 的消警状态存在 `ui-state.json`（`{schema, sessions: {id: {acknowledged_at}}}`），hook 不读也不写。
- 列表里的“隐藏/已结束”是 app 每轮**派生**出来的（pid 存活 + 宽限期），不持久化；这样 resume 复用了同一个 session_id 时，新事件能让它自动重新出现。

### 6.2 状态与聚合优先级

聚合颜色（收起态外圈/光晕）：

1. `waiting_permission`（未消警）→ 红色脉冲（最高优先级）
2. `waiting_permission`（已消警）→ 红色常亮，不脉冲
3. `error` → 琥珀色常亮
4. `running` → 绿色（小球外圈绿色）
5. `done` → 绿色常亮
6. `idle` → 灰色
7. `ended` → 不参与聚合，短暂显示后移除

每个小点的颜色使用各自会话的状态颜色；只有**未消警**的 `waiting_permission` 会让整球红色脉冲。已消警的等待会话仍在列表里显示红色“等待授权”，但不再打扰。

### 6.3 状态机

```
SessionStart(startup/fork) ──► idle
SessionStart(resume) ────────► 重解析终端/pid；ended/error/running/waiting→idle；done 保留
SessionStart(clear) ─────────► idle（重置 current_tool）
SessionStart(compact) ───────► 保留状态
UserPromptSubmit ────────────► running（turn_started_at=now）
PreToolUse ──────────────────► running（current_tool=工具名）
PostToolUse ─────────────────► running（current_tool=nil；清 waiting）
PermissionRequest ───────────► waiting_permission（waiting_since=now）
PermissionDenied ────────────► running（清 waiting）
Notification(permission_prompt / agent_needs_input) ─► waiting_permission
Notification(idle_prompt) ───► done
Stop ────────────────────────► done（turn_ended_at=now）
StopFailure ─────────────────► error（turn_ended_at=now）
SessionEnd ──────────────────► ended
```

清除等待态：`PostToolUse`、`PermissionDenied`、`Stop`、`StopFailure`、`UserPromptSubmit`、`SessionEnd`。
**`PreToolUse` 不清除**——它在授权提示之前触发，不代表用户已批准。

消警（UI-only，不改变 session 状态，写入 `ui-state.json`）：

- **只有确认该会话所在标签页/面板成为活动**时才标记 `acknowledged_at`（判定方法见 §7.4）：
  - 终端 app 不是前台 → 不消警；
  - 终端在前台，但当前活动的是同一终端的**另一个标签页/面板** → 不消警；
  - 该会话的标签页/面板成为活动 → 消警。
- 点击任务行触发跳转后，仍以 §7.4 的活动标签确认结果为准：跳转成功且确认激活 → 消警；跳转失败或无法确认 → 不消警。
- 无法精确确认的终端（Ghostty id 对不上、unknown/headless、Kaku 活动 pane 查询不可用）→ 不自动消警；用户可右键“忽略本次提醒”手动消警。
- 已消警的会话仍是 `waiting_permission`，列表显示红色“等待授权”，但整球不再红闪；右键“重新提醒”会清除 `acknowledged_at`，恢复脉冲。
- 下一个改变状态的 hook 事件到来时，app 清除该会话的 `acknowledged_at`。
- 轮询只在存在未消警 waiting 时进行（建议 1 秒一次），没有等待会话时停止。
- 如果 `PermissionRequest` 之后没有任何事件（极端情况），右键“忽略本次提醒”只影响 UI，不伪造状态；真实状态保持到下一个事件或进程退出。

### 6.4 存活与清理

- App 每 5 秒检查 `claude_pid`：
  - `kill(pid, 0)` 判断进程是否存在；
  - 同时用 `proc_pidpath(pid)` 与 session 里保存的 `claude_exec_path` 比对，降低 PID 复用误判。
- 进程不存在（或路径不匹配）时，**所有状态都在宽限期后隐藏**，`done` / `idle` 不例外：
  - 第一次发现进程消失时记下 `missing_since`；
  - 宽限期 3 秒；3 秒后仍不存在 → 该行隐藏；
  - 宽限期内收到新的 hook 事件（如 resume 的新 `SessionStart`、新 pid）→ `missing_since` 清零，行继续显示。
- 这样“任务完成后关标签页”的 `done` 行不会残留：
  - Claude Code 正常退出并触发 `SessionEnd` → ended，3 秒后移除；
  - 直接关标签页/SIGHUP 导致 `SessionEnd` 没触发 → 5 秒轮询 + 3 秒宽限，最多约 8 秒内隐藏；
  - App 当时没运行 → 下次启动时读文件、查 pid，同样隐藏。
- 任务执行中关闭标签页：pid 消失，最多约 8 秒内隐藏；session 文件可能仍写着 running，但 UI 不显示；App 重启后同样按 pid 隐藏。
- 如果 Claude 跑在 tmux/screen 里、标签页关了但进程还活着：HUD 仍会显示它（它反映的是进程，不是标签页）；此时跳转目标可能已失效，点击会失败并提示。
- session 文件不即时删除（避免和 hook 写入竞争）；App 启动时清理 `updated_at` 超过 7 天的文件，并清理 `ui-state.json` 中已不存在的会话。
- 运行中的长任务不因“长时间无事件”被误判为结束（只以进程存活为准）。
- `done` 且进程仍在（标签页还开着）→ 保持显示，直到 SessionEnd/进程退出；这是预期行为。

## 7. 终端定位与跳转

### 7.1 识别（hook 首次事件时解析一次并写入 session 文件）

| 终端 | 环境变量识别 | 精确标识 | 备注 |
|---|---|---|---|
| iTerm2 | `TERM_PROGRAM=iTerm.app` | `ITERM_SESSION_ID`（`w0t0p0:UUID`）或 tty | 3.7.7 |
| Terminal.app | `TERM_PROGRAM=Apple_Terminal` | tty | 用 tab 的 `tty` 属性匹配 |
| Kaku | `TERM_PROGRAM=Kaku` | `WEZTERM_PANE` | 0.30.0；WezTerm mux 协议 |
| Ghostty | `TERM_PROGRAM=ghostty` | `GHOSTTY_SURFACE_ID`（1.4.0） | 先验证 AppleScript terminal id 是否一致；否则按 cwd |

辅助手段：

- tty 通过父进程链获取：hook → shell → claude，找到有控制终端的 claude 进程，用 `ps -o tty=` 或 `sysctl` 读取。
- **每个 `SessionStart`（包括 resume）都重新解析终端、tty、`claude_pid`**：resume 可能换到新标签页或新进程，旧上下文会点错标签、并让存活检查误判。若 SessionStart 缺失（hooks 中途安装），则在第一个事件解析。
- 检测不到终端（`claude -p`、launchd/无 TTY）：`terminal.app = unknown`。列表照常显示该会话，但点击行不跳转，显示“未检测到可跳转的终端”；不影响进度和授权提醒。
- 如果环境变量缺失，沿父进程路径匹配四个 app 的 bundle id：
  - iTerm2 `com.googlecode.iterm2`
  - Terminal `com.apple.Terminal`
  - Ghostty `com.mitchellh.ghostty`
  - Kaku `fun.tw93.kaku`

### 7.2 跳转实现

**iTerm2（精确）**

```applescript
tell application "iTerm2"
  repeat with w in windows
    repeat with t in tabs of w
      repeat with s in sessions of t
        if id of s is "UUID" then
          select s
          activate
          return
        end if
      end repeat
    end repeat
  end repeat
end tell
```

匹配失败时用 `tty of s` 兜底。

**Terminal.app（精确）**

```applescript
tell application "Terminal"
  repeat with w in windows
    repeat with t in tabs of w
      if tty of t is "/dev/ttys003" then
        set selected tab of w to t
        set index of w to 1
        activate
        return
      end if
    end repeat
  end repeat
end tell
```

**Kaku（精确）**

```bash
/Applications/Kaku.app/Contents/MacOS/kaku cli activate-pane --pane-id "$WEZTERM_PANE"
```

然后激活 Kaku app（`NSRunningApplication.activate`）。如果 Kaku 未运行，`open -a Kaku`。
`kaku cli` 已确认支持 `activate-pane` / `activate-tab`（0.30.0）。

**Ghostty（best-effort）**

1. 如果 `GHOSTTY_SURFACE_ID` 存在，尝试：

```applescript
tell application "Ghostty"
  set hits to every terminal whose id is "SURFACE_ID"
  if (count of hits) > 0 then
    focus (item 1 of hits)
    activate
    return
  end if
end tell
```

2. id 匹配失败（例如 AppleScript id 与 surface id 不是同一套标识）时，退回按 `working directory` 匹配；同目录多标签时选第一个，可能点错。
3. 再失败则只激活 Ghostty app。

**未知终端（unknown）/ headless**

- 不执行任何 AppleScript 或 Kaku CLI。
- 行内显示“未检测到可跳转的终端”；右键可复制 `session_id` / `cwd` / tty 供排查。
- 授权提醒、跑马灯、列表计数仍然工作；只是不能一键跳转。

> 已验证 Ghostty 1.4.0 支持 AppleScript（application → windows → tabs → terminals）以及 `GHOSTTY_SURFACE_ID`（PR #12027，1.4.0 milestone）。实现阶段会先用一个真实 Ghostty 标签验证 id 对应关系。

### 7.3 安全与权限

- 所有插入 AppleScript 的值先校验：
  - tty：`^/dev/tty[a-zA-Z0-9]+$`
  - session UUID：`^[A-Za-z0-9-]{8,64}$`
  - Kaku pane id：`^[0-9]{1,20}$`
  - Ghostty surface id：`^[0-9a-fA-F]{1,32}$`（十进制或十六进制，比较一律按字符串）
  - cwd：拒绝换行/控制字符，转义 `\` 和 `"`
- 首次点击跳转时 macOS 会弹“AgentDot 想要控制 iTerm2/Terminal/Ghostty”，在 `Info.plist` 写 `NSAppleEventsUsageDescription`。
- 用户拒绝自动化权限时：不崩溃，行内显示“无法跳转，请在系统设置 → 隐私与安全 → 自动化中允许”，并提供“复制终端信息”按钮。
- Kaku 走 CLI，不需要 Apple Events 权限。

### 7.4 活动标签/面板检测（消警依据）

App 只在该会话状态为 `waiting_permission` 且尚未消警时轮询（1 秒一次）。先检查对应终端 app 是否前台，再查询该终端当前活动的标签/面板：

| 终端 | 查询方式 | 精确性 |
|---|---|---|
| iTerm2 | AppleScript：`current session of current window`，比较 session `id`（或 tty） | 精确 |
| Terminal | AppleScript：`selected tab of front window`，比较 tab `tty` | 精确 |
| Kaku | `kaku cli list --format json` 或 `list-clients`，找出 focused pane，与 `WEZTERM_PANE` 比较（实现阶段验证字段） | 精确（需验证 CLI 字段） |
| Ghostty | AppleScript：`focused terminal of selected tab of front window`，比较 terminal `id`；id 对不上时比较 `working directory` + `name` | `id` 可用时精确；否则不自动消警 |
| unknown | 无 | 不自动消警 |

- AppleScript 用 `NSAppleScript` 在 app 进程内执行，避免每秒 spawn `osascript`。
- 查询失败、自动化权限被拒、结果不确定 → 一律视为“未确认”，不消警。
- 点击任务行跳转后，同样走这张表确认；确认通过才消警。
- 这是启发式：用户切到该标签页但没批准就离开，脉冲会停止；行仍是红色常亮，可用“重新提醒”恢复；`PostToolUse`/`Stop`/`PermissionDenied` 到来时状态会纠正。
- 轮询只针对未消警的等待会话；没有等待会话时不查询任何终端。

## 10. 安全与隐私

- **不联网**：整个项目不使用网络 API；状态只落本地文件。
- **不存内容**：不保存 prompt、tool_input、tool_response、notification message、last_assistant_message；只保存枚举/工具名/路径/终端标识。
- **不代答授权**：`dot-hook` 对 `PermissionRequest` 不输出任何决策 JSON；Claude 始终走自己的授权 UI。
- **写权限分离**：hook 独占写 session JSON；app 独占写 `ui-state.json`；两边都不修改对方文件，避免并发回滚。
- **AppleScript 注入防护**：所有外部值先正则校验再转义；Kaku pane id 只接受数字。
- **文件权限**：状态目录 0700、文件 0600、helper 0755（仅当前用户可执行）。
- **Hook 不阻塞**：5 秒超时、永远 exit 0、错误只写本地日志。
- **配置安全**：修改 `settings.json` 前备份；只增删自己的 handler；保留现有 hooks；原子写。

## 11. 边界与错误处理

| 场景 | 处理 |
|---|---|
| hook stdin 不是合法 JSON | 记日志，exit 0 |
| settings.json 不是合法 JSON | 不修改，报错并提示备份/手动修复 |
| settings.json 是 symlink | 写解析后的目标，保留 symlink |
| helper 不存在/不可执行 | 面板显示“Hooks 未安装”，提供一键修复 |
| App 启动时已有旧会话文件 | 读取；ended/过期文件按 6.4 清理 |
| 同一 session 并发事件 | `flock` 串行化；最后一次写入生效 |
| 用户拒绝自动化权限 | 行内提示 + 复制终端信息；不崩溃 |
| Ghostty id 匹配失败 | 按 cwd 匹配；再失败只激活 app |
| 多屏/屏幕拔出 | clamp 到可见区域 |
| 全屏应用覆盖悬浮球 | 用 `.statusBar` + `.fullScreenAuxiliary`；实测不足时提升窗口 level |
| 深色/浅色模式 | 系统语义色 + material 自动适配 |
| 减弱动态效果 | 跑马灯静态、红闪改为颜色深浅变化 |
| Claude 进程被杀 / 关闭标签页 | 5 秒轮询 + 3 秒宽限，最多约 8 秒隐藏；`done`/`idle` 不例外 |
| 任务完成后关闭标签页 | `SessionEnd` 触发则 3 秒移除；否则进程检查兜底隐藏，不留绿色残留 |
| 标签页关了但 tmux 里进程还活着 | HUD 继续显示（它反映进程）；跳转可能失效并提示 |
| 长任务长时间无事件 | 只要进程存活就保持 running，不误判 |
| 授权提示后用户拒绝 | `PermissionDenied` 清 waiting；若该事件未触发，下一个 PreToolUse/Stop 会清理 |
| 批准后长命令运行中 | 只有切到该会话所在标签页/面板（或点击行跳转并确认激活）才消警；状态仍 waiting，直到 PostToolUse/Stop 证明已处理 |
| 同一终端的其他标签页变为活动 | 不消警，继续脉冲 |
| PreToolUse 早于授权提示 | 不用 PreToolUse 清 waiting；见 §5.1 时序 |
| app 与 hook 并发写 | hook 独占 session JSON；app 只写 `ui-state.json` |
| resume 换标签页/新进程 | 每个 SessionStart 重解析终端与 pid |
| 未知/headless 终端 | 列表显示、禁用跳转、提示“未检测到终端” |
| 设置 N 大于 9 | 限制 1–9；展开列表始终显示全部会话 |
| `PermissionRequest` 之后没有任何事件 | 右键“忽略本次提醒”只影响 UI；真实状态保留到下一个事件/进程退出 |

## 12. 验证计划

### 12.1 单元测试（swift test）

- `StateReducerTests`
  - 每个事件 → 期望状态；未知事件 no-op；非法 JSON 不崩溃。
  - `PreToolUse` **不**清除 waiting_permission；`PostToolUse` / `PermissionDenied` 才清除。

  - 聚合优先级：未消警 waiting > 已消警 waiting > error > running > done > idle。
- `UIStateStoreTests`
  - 消警/重新提醒/隐藏的持久化；新等待事件清除旧 `acknowledged_at`；不修改 session JSON。
- `SettingsMergerTests`
  - 保留现有 `cc-status` handler；幂等；重复安装不产生重复项。
  - 备份文件生成；symlink 场景；非法 JSON 不写入。
- `TerminalContextTests`
  - 四个终端的环境变量识别；tty/pane/surface 校验；AppleScript 转义。
- `SessionFileStoreTests`
  - 原子写、损坏文件忽略、并发写不撕裂、过期清理。

### 12.2 集成测试（脚本）

`scripts/simulate.sh` 依次向 `dot-hook emit` 灌入：

```
允许分支：SessionStart → UserPromptSubmit → PreToolUse → PermissionRequest
         → PostToolUse（批准且工具执行完）→ Stop → SessionEnd
拒绝分支：SessionStart → UserPromptSubmit → PreToolUse → PermissionRequest
         → PermissionDenied → Stop → SessionEnd
resume：  SessionStart(startup) → ... → SessionEnd → SessionStart(resume, 新 tty/pid)
```

断言每个阶段的状态文件字段（jq）、stdout 为空、exit 0；并断言 `PreToolUse` 不会把 waiting 改回 running。

## 13. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| Claude Code hook 字段/事件随版本变化 | 状态不准 | 以 `hook_event_name` 为准；未知事件忽略；官方文档 + 回归测试 |
| PermissionRequest 与 Notification 重复触发 | 重复写 | 幂等状态写 + flock；两次都写 waiting 也无害 |
| 没有“已批准”事件 | 批准后红闪持续到工具结束 | 精确活动标签消警 + `PermissionDenied` + `PostToolUse` 兜底 |
| 活动标签查询失败/自动化权限被拒 | 无法自动消警 | 视为未确认，继续脉冲；保留手动“忽略本次提醒” |
| Ghostty id 对不上 / Kaku 活动 pane 字段不可用 | 无法精确确认 | 不自动消警，保留手动忽略 |
| app 与 hook 同时写 session | 状态回滚/丢更新 | hook 独占 session JSON，app 只写 `ui-state.json` |
| resume 换标签页/新进程 | 跳错/存活误判 | 每个 SessionStart 重解析终端与 pid |
| 未知/headless 终端 | 无法跳转 | 列表显示但禁用跳转，明确提示 |
| Ghostty AppleScript id 与 surface id 不一致 | 跳错标签 | 实现前先做 5 分钟验证；失败按 cwd；用户已接受 best-effort |
| 自动化权限被拒 | 无法跳转 | 行内提示 + 复制终端信息；不崩溃 |
| 全屏覆盖 | 小球被挡住 | `.statusBar` + `.fullScreenAuxiliary`；实测后调整 level |
| 合并 settings.json 破坏现有 hooks | 用户 hook 失效 | 备份 + 只增删自己的 handler + 校验 + 卸载测试 |
| ad-hoc 签名 + LaunchAgent | 自启失败 | LaunchAgent 直接跑可执行文件；不依赖 SMAppService |
| 多事件并发写文件 | JSON 撕裂 | flock + 临时文件 rename |
| PID 复用导致存活误判 | 会话残留 | `kill(0)` + `proc_pidpath` 与 `claude_exec_path` 比对；路径拿不到时宁可隐藏 |
| 用户长时间离开，授权红闪持续 | 提醒疲劳 | 这是预期行为；提供“忽略本次提醒” |

## 16. 已确认决策（builder check Q1）

**Q1：批准授权后，红闪什么时候停止？ → 方案 3：精确到标签页/面板。**

- 只有确认该会话所在标签页/面板成为活动时才消警；点击行跳转也以 §7.4 的确认结果为准。
- 同一终端的其他标签页/面板、或只激活终端 app，不消警。
- 无法精确确认的终端（Ghostty id 对不上、unknown/headless、Kaku 活动 pane 查询不可用）不自动消警，保留手动“忽略本次提醒”。
- 状态仍为 `waiting_permission`，直到 `PostToolUse`/`Stop`/`PermissionDenied` 证明已处理；消警只停止脉冲，行仍红色常亮。
